# 战术上下文特征（TacticContext）完整说明

## 概述

战术上下文特征由 `TacticContext.build_features()` 在 `obs_builder.py` 中调用生成，总维度 **143**（`Args.DIM_TACTIC`）。它和实体特征（`DIM_ENTITY`）拼接后形成完整观测 `DIM_ALL`，送入模型。

在模型 `forward()` 中，战术特征从 `feature_vec` 中独立切出，独自走一路 MLP：

```python
entity_vec, tactic_vec = feature_vec.split([DIM_ENTITY, DIM_TACTIC], dim=1)
tactic_result = self.tactic_mlp(tactic_vec)  # 143 → 128 → 64
```

最终和 LSTM 输出（512）+ MLP 旁路（512）拼接成 1088 维。

## 事实采集（_collect_facts）

在生成特征之前，`_collect_facts` 从 `Info` 对象中提炼出约 40 个布尔/数值事实，作为后续所有特征组的原材料。关键事实包括：

| 事实 | 类型 | 含义 |
|---|---|---|
| `enemy_visible` | bool | 敌方英雄是否可见（距离 < 999999） |
| `enemy_distance` | float | 到敌方英雄的 L2 距离 |
| `self_hp_rate` | float | 自身血量比例 (0~1) |
| `enemy_hp_rate` | float | 敌方血量比例 (0~1) |
| `hp_advantage` | float | 血量优势 = 自比率 - 敌比率 (-1~1) |
| `trade_active` | bool | 是否在对拼（敌人可攻击范围内且双方存活） |
| `frenzy_ready` | bool | 召唤师技能（狂暴）是否可用 |
| `frenzy_active` | bool | 狂暴 buff 是否当前生效中 |
| `enemy_soldier_count` | int | 敌方存活小兵数量 |
| `our_soldier_count` | int | 我方存活小兵数量 |
| `nearest_enemy_hp_rate` | float | 最近敌方小兵的血量比例 |
| `lane_cleared` | bool | 兵线是否清完（敌方小兵=0） |
| `lane_advancing` | bool | 兵线是否推进中（我方兵入敌方塔下 或 数量占优） |
| `last_hit_window` | bool | 最近小兵血量 ≤25%，可补刀 |
| `crab_visible` | bool | 河蟹是否可见 |
| `crab_distance` | float | 到河蟹的距离 |
| `crab_hp_rate` | float | 河蟹血量比例 |
| `crab_safe_to_attack` | bool | 攻击河蟹是否安全（自身>45%血 且 敌远离） |
| `our_soldier_in_enemy_tower` | bool | 我方小兵是否在敌方防御塔范围内 |
| `enemy_tower_target_type` | str | 敌方防御塔当前攻击目标类型：none/hero/soldier |
| `self_in_enemy_tower_range` | bool | 自身是否在敌方防御塔攻击范围内 |
| `tower_attack_window` | bool | 塔下攻击窗口（我方兵扛塔 + 塔打小兵 + 敌远离） |
| `tower_danger` | bool | 塔下危险（自己在塔范围内 + 塔以自己为目标） |
| `self_low_hp` | bool | 自身低血量（≤35%） |
| `self_low_ep` | bool | 自身低蓝量（≤60） |
| `recover_ready` | bool | 回复技能是否可用 |
| `recall_ready` | bool | 回城是否可用 |
| `our_cake_available` | bool | 我方血包是否存在 |
| `cake_distance` | float | 到血包的距离 |
| `enemy_dead_or_far` | bool | 敌方死亡 或 距离>9000 |
| `safe_recall_window` | bool | 安全回城窗口（兵线清完 + 敌远离 + 低血量） |
| `self_in_grass` | bool | 自身是否在草丛中 |
| `enemy_near_grass` | bool | 敌人在草丛附近（自身在草 + 敌可见 + 距离≤6500） |
| `enemy_luban_ult_active` | bool | 敌方鲁班大招飞艇是否存在 |
| `enemy_luban_ult_distance` | float | 到敌方鲁班大招最近子弹的距离 |
| `enemy_luban_ult_inside` | bool | 是否在鲁班大招危险范围内（≤3200） |
| `enemy_luban_ult_near` | bool | 是否在鲁班大招警告范围内（≤5400） |
| `enemy_luban_ult_moving_away` | bool | 是否正在远离鲁班大招（距离增大≥450） |

## 九大特征组详细拆解

### 1. 战斗状态特征 `_combat_features` — 22 维

| 维度范围 | 内容 | 编码方式 |
|---|---|---|
| 0 | 敌方是否可见 | 标量 0/1 |
| 1–5 | 敌方距离分桶 | one-hot(5)：≤1400 / ≤4500 / ≤8500 / ≤16000 / >16000或不可见 |
| 6–9 | 自身血量分桶 | one-hot(4)：≤25% / ≤50% / ≤75% / >75% |
| 10–13 | 敌方血量分桶 | one-hot(4)：同上 |
| 14–18 | 血量优势分桶 | one-hot(5)：≤-50% / ≤-15% / ≤15% / ≤50% / >50% |
| 19 | 是否在对拼 | 标量 0/1 |
| 20 | 狂暴是否可用 | 标量 0/1 |
| 21 | 狂暴是否生效中 | 标量 0/1 |

**设计意图**：给模型一个清晰的"能不能打、该不该打"的画面——敌人多远、双方血量对比、有没有狂暴在手。

---

### 2. 连招状态特征 `_combo_features` — 33 维

| 维度范围 | 内容 | 编码方式 |
|---|---|---|
| 0 | 英雄身份 | 标量：鲁班=-1, 狄仁杰=1 |
| 1–7 | 连招阶段 | one-hot(7)：idle / opener / after_skill / expect_normal_attack / follow_up_skill / finish / failed_timeout |
| 8–19 | 上一帧按下的按钮 | one-hot(12)：0=无动作, 1=无动作, 2=移动, 3=普攻, 4=1技能, 5=2技能, 6=3技能, 7=回复, 8=召唤师技能, 9=回城, 10=4技能(无用), 11=装备技能 |
| 20 | 1技能是否可用 | 标量 0/1 |
| 21 | 2技能是否可用 | 标量 0/1 |
| 22 | 3技能是否可用 | 标量 0/1 |
| 23 | 回复是否可用 | 标量 0/1 |
| 24 | 召唤师技能是否可用 | 标量 0/1 |
| 25 | 回城是否可用 | 标量 0/1 |
| 26–31 | 被动层数 | one-hot(6)：0~5层（鲁班火力压制最多4层，狄仁杰迅捷最多5层） |
| 32 | 是否有近期的攻击落空 | 标量 0/1（普攻命中率<100% 或 技能命中率<100%） |

**连招阶段状态机**：`_update_combo` 根据按钮和当前阶段更新状态：

- **鲁班 (112)**：技能3(6)起手 → 任何技能 → 普攻 → 跟进技能
- **狄仁杰 (133)**：技能3(6)起手 → 技能1(4) → 普攻 → 收尾

超时（>90帧未推进阶段）则标记 `failed_timeout`。

**设计意图**：让模型知道"我在连招的哪个阶段"，从而学会技能释放的时序节奏。鲁班和狄仁杰的连招节奏不同，hero_id 区分了两个英雄的行为偏好。

### 3. 兵线状态特征 `_lane_features` — 17 维

| 维度范围 | 内容 | 编码方式 |
|---|---|---|
| 0–4 | 敌方存活小兵数 | one-hot(5)：0~4+（截断到4） |
| 5–9 | 我方存活小兵数 | one-hot(5)：同上 |
| 10–13 | 最近敌方小兵血量 | one-hot(4)：≤25% / ≤50% / ≤75% / >75% |
| 14 | 兵线是否清完 | 标量 0/1 |
| 15 | 兵线是否推进中 | 标量 0/1（我方兵入敌方塔下 或 数量占优） |
| 16 | 是否可补刀 | 标量 0/1（最近小兵血量≤25%） |

**设计意图**：传统 MOBA 对线的基础——控线、推线、补刀的时机判断。兵线推过去才能点塔，兵线清完才能安全回城或打河蟹。

### 4. 河蟹状态特征 `_crab_features` — 10 维

| 维度范围 | 内容 | 编码方式 |
|---|---|---|
| 0 | 河蟹是否可见 | 标量 0/1 |
| 1–4 | 河蟹距离分桶 | one-hot(4)：≤1800 / ≤6500 / ≤14000 / >14000或不可见 |
| 5–8 | 河蟹血量分桶 | one-hot(4)：≤25% / ≤50% / ≤75% / >75% |
| 9 | 攻击河蟹是否安全 | 标量 0/1（自身>45%血 且 敌远离或死亡） |

**设计意图**：河蟹是 1v1 对线中的重要中立资源。模型需要知道什么时候可以去争夺河蟹——敌方不在的时候安全吃，敌人在的时候去可能被消耗。

### 5. 防御塔状态特征 `_tower_features` — 10 维

| 维度范围 | 内容 | 编码方式 |
|---|---|---|
| 0 | 我方小兵是否在敌方塔下 | 标量 0/1 |
| 1–4 | 敌方塔攻击目标类型 | one-hot(4)：无目标 / 英雄 / 小兵 / 未知 |
| 5 | 自身是否在敌方塔范围内 | 标量 0/1 |
| 6–8 | 塔下危险等级 | one-hot(3)：安全（有兵扛塔+打小兵） / 中立（在塔范围但没被锁定） / 危险（塔以自己为目标） |
| 9 | 塔下攻击窗口 | 标量 0/1（有兵扛塔 + 塔打小兵 + 敌远离或死亡） |

**设计意图**：防御塔是前期最重要的威慑。模型需要区分"有兵线扛塔可以安全点塔"和"被塔打要立刻撤退"两种完全不同的局面。

| 1 | 自身低蓝量（≤60） | 标量 0/1 |

| 4 | 我方血包是否存在 | 标量 0/1 |

### 7. 攻击精度特征 `_accuracy_features` — 22 维

| 维度范围 | 内容 | 编码方式 |
|---|---|---|
| 0–3 | 近期普攻次数 | one-hot(4)：0/1/2/3+ 次（在窗口内） |
| 4–8 | 普攻命中率分桶 | one-hot(5)：≤20% / ≤40% / ≤60% / ≤80% / >80% |
| 9–12 | 近期技能攻击次数 | one-hot(4)：同上 |
| 13–17 | 技能命中率分桶 | one-hot(5)：同上 |
| 18–21 | 连续空攻击次数 | one-hot(4)：0/1/2/3+ 次 |

这些统计来自 `TacticContext` 内部维护的 `normal_results` 和 `skill_results` 双端队列（窗口 `ATTACK_WINDOW_SIZE=12` 帧），以及 `empty_attack_streak` 连续落空计数器。

**设计意图**：让模型感知自己的攻击质量——连续空 A 说明站位不对或距离判断有问题，需要调整。高命中率说明当前操作是有效的。

### 8. 草丛伏击特征 `_ambush_features` — 8 维

| 维度范围 | 内容 | 编码方式 |
|---|---|---|
| 0 | 自身是否在草丛中 | 标量 0/1 |
| 1 | 敌人在草丛附近 | 标量 0/1（自己在草 + 敌可见 + 距离≤6500） |
| 2–5 | 蹲草等待时长分桶 | one-hot(4)：≤15帧 / ≤45帧 / ≤90帧 / >90帧 |
| 6 | 伏击条件就绪 | 标量 0/1（在草里 + 敌人在攻击范围内） |
| 7 | 是否刚出草丛（12帧内） | 标量 0/1 |

`TacticContext` 维护了 `grass_wait_frames`（连续在草中的帧数）和 `ambush_exit_frames`（出草后持续12帧的标记）。

**设计意图**：草丛是 MOBA 中重要的战术要素——蹲草可以获取先手优势。这个特征让模型学会"在草里等多久该出手"以及"出草后短时间内仍有伏击加成"。

### 9. 敌方鲁班大招特征 `_luban_ult_features` — 10 维

| 维度范围 | 内容 | 编码方式 |
|---|---|---|
| 0 | 敌方鲁班大招是否活跃 | 标量 0/1 |
| 1 | 是否在危险范围内 | 标量 0/1（距离≤3200） |
| 2 | 是否在警告范围内 | 标量 0/1（距离≤5400） |
| 3 | 是否正在远离 | 标量 0/1（上一帧到这一帧距离增加≥450） |
| 4–7 | 到飞艇子弹的距离分桶 | one-hot(4)：≤1800 / ≤6500 / ≤14000 / >14000或不存在 |

**设计意图**：鲁班大招飞艇是持续性减速+伤害区域。模型需要学会看到飞艇子弹就远离，而不是傻站在里面被打。这是专门针对鲁班对局的安全特征。

## 与原始实体特征的关系

战术特征（143维）和实体特征（DIM_ENTITY）**互补而非重复**：

- **实体特征**：低层次感知——"敌人在坐标 (12345, -6789)，血量 1800/2400，处于 UseSkill_1 状态"
- **战术特征**：高层次提炼——"敌人离我 3500 单位（中等距离），我方血量优势 15%，正在对拼中，敌方塔正在打我，狂暴还没用"

战术特征的每一项都是对原始信息的**规则化抽象**和**时序聚合**（如命中率是滑动窗口统计、连招阶段是状态机、蹲草时长是帧计数器）。这让模型不需要自己从原始坐标中"悟出"这些战术概念——而是直接获得一个结构化的战术画布。
